# PRD — AI 귀갓길 안심 도우미

> 버전: 0.5
> 작성일: 2026-10-30
> 상태: 승인
> 기간: 3일 MVP  
> 기술: React, Python 3.11, FastAPI, PostgreSQL, Docker
> 배포 환경: AWS 클라우드 (컨테이너 실행 서비스 미정)
> 대상: 어두운 시간대에 혼자 귀가하며 경로와 주변 안전정보를 확인하고 싶은 사람, 특히 여성

---

## 1. 제품 요약

AI 귀갓길 안심 도우미는 사용자가 출발지·도착지·시간·경로 선호를 입력하면 보행 경로 후보와 확인 가능한 안전정보를 비교하고, 추천 근거와 데이터의 한계를 설명하는 모바일 우선 웹 서비스다. 사용자가 원하면 검증된 공식 서울시 안심서비스 안내 또는 앱으로 이동할 수 있다.

이 프로젝트의 Auto Healing 대상은 웹 서비스 자체의 사용자 안전 판단이 아니라, 경로·범죄주의구간·안전시설 데이터 연동 및 허용된 테스트 프로세스다. 오류가 해결되지 않거나 정보의 정확성을 확인할 수 없으면 해당 정보를 제공하지 않는 방식으로 안전하게 제한한다.

## 2. 문제와 기회

야간에 혼자 이동하는 사용자는 이동시간뿐 아니라 큰길 선호, 계단 회피, 주변 안전정보를 함께 고려하고 싶을 수 있다. 현재 제안은 여러 종류의 지도·공공 안전정보를 한 번에 비교하고, 동행 지원이 필요할 때 공식 절차를 찾는 부담을 줄이는 것이다.

잘못되거나 누락된 안전정보는 사용자의 위험 판단을 왜곡할 수 있다. 따라서 이 제품은 위험을 없애거나 귀갓길의 안전을 보장하는 서비스가 아니며, 데이터 출처·기준시각·누락 여부를 함께 설명하고 불확실할 때 안전성을 단정하지 않는다.

## 3. 목표 및 비목표

### 목표

1. 출발지·도착지, 출발/도착 시각, 빠른 길·큰길·계단 회피 선호를 입력받는다.
2. 보행 경로 후보의 이동시간과 확보 가능한 범위의 범죄주의구간·조명·비상벨 정보를 나란히 비교한다.
3. 추천 이유를 데이터 근거와 함께 설명하며, 데이터가 없거나 갱신시각을 확인할 수 없으면 그 한계를 표시한다.
4. 사용자가 원할 때 검증된 공식 안심서비스 안내·앱 이동을 제공한다.
5. 의존 서비스 장애를 격리된 환경에서 반복 재현하고, 제한된 복구와 독립 검증을 시연한다.

### 비목표

- 귀갓길 안전 보장, 범죄 발생 예측, 위험 점수로 사용자에게 확정적 안전 순위를 부여.
- 긴급 신고, 실시간 관제·추적, 보호자 위치 공유.
- 안심귀가스카우트 이용 자격·운영 여부·예약 가능 여부의 자체 판정 및 예약 자동 제출.
- 사용자 계정, 결제, 위치 이력 저장, 상용 운영 배포. Day 3의 제한된 AWS 샌드박스 데모 배포는 포함할 수 있다.
- LLM의 자유형 명령 실행이나 운영 시스템에 대한 자율 변경.

## 4. 사용자와 사용 맥락

### 주요 사용자

- 어두운 시간대에 혼자 귀가하며 경로 특성을 미리 확인하려는 사람.
- 특히 밤길 이동 시 큰길, 계단 회피, 주변 안전시설 정보를 중요하게 보는 여성.

### 사용 사례

> 사용자가 “금요일 밤 11시쯤 역에 도착해요. 집까지 큰길로 가고 싶고, 동행 지원도 알아보고 싶어요.”라고 조건을 입력한다. 서비스는 이용 가능한 보행 경로와 확인된 데이터만 비교해 이유를 설명하고, 사용자가 원하면 공식 안심서비스 절차로 이동시킨다.

이 예시는 사용자 입력 방식 설명이며, 출발지·도착지를 실제로 저장하거나 운영기관의 서비스 제공 가능성을 보장하지 않는다.

## 5. 핵심 사용자 여정

1. **조건 입력:** 출발지와 도착지, 출발 또는 도착 시각, 빠른 길·큰길 선호·계단 회피 등 선택 조건을 입력한다.
2. **경로 조회:** 보행 경로 제공자에게 후보 경로와 이동시간을 요청한다.
3. **안전정보 조회:** 행정안전부 생활안전지도 범죄주의구간 WMS와 출처가 확인된 안전시설 정보를 조회한다.
4. **경로 비교:** 조회에 성공한 정보만 표시하고 경로별 차이와 추천 이유를 설명한다. 계산할 수 없는 정보는 추정하지 않는다.
5. **정보 한계 안내:** 제공자 오류, 데이터 누락, 갱신시각 미확인 시 어떤 정보가 부족한지 알린다.
6. **공식 서비스 연결:** 사용자가 선택한 경우 확인된 공식 서울시 안심서비스 안내 또는 앱으로 연결한다. 앱이 설치되지 않았거나 딥링크가 미확인인 경우 공식 안내 페이지를 사용한다.

## 6.1 애플리케이션 구조 및 테스트 요구사항

- 웹 화면은 React SPA, API 서버는 Python 3.11 기반 FastAPI로 구현한다. Flask는 사용하지 않는다.
- 프런트엔드와 백엔드는 다음과 같이 분리하고 MVC 책임을 계층에 맞게 둔다.
  - `frontend/src/views/`: React 페이지와 표시 컴포넌트(View)
  - `frontend/src/controllers/`: 화면 이벤트·상태 흐름(Controller)
  - `frontend/src/models/`: 화면에서 사용하는 데이터 타입과 모델(Model)
  - `backend/app/controllers/`: FastAPI 요청 라우터와 입출력 연결(Controller)
  - `backend/app/models/`: 도메인·요청/응답·PostgreSQL 모델(Model)
  - `backend/app/services/`: 외부 API 어댑터와 Auto Healing 업무 로직
- 테스트 코드는 기능 구현과 함께 작성한다. `tests/unit/`에는 React 화면/컨트롤러와 Python 모델·서비스·컨트롤러 단위 테스트를, `tests/integration/`에는 FastAPI HTTP 흐름·PostgreSQL·모의 외부 제공자 통합 테스트를 둔다.
- 각 테스트는 격리 가능한 입력을 쓰고 실제 사용자 위치·외부 운영 API·AWS 비용 발생 리소스에 의존하지 않는다. 외부 데이터 장애는 격리 모의 제공자로 주입한다.

## 7. 안전·신뢰 요구사항

- 화면은 “안전한 길”, “범죄가 없는 길”, “안전 보장”처럼 검증할 수 없는 확정 표현을 쓰지 않는다.
- 경로 추천은 “선호 조건 및 확인 가능한 정보에 따른 비교”로 설명하고, 제공자와 데이터 기준시각을 표시한다.
- WMS 이미지만 확보된 경우에는 시각적 레이어로 제시할 수 있지만, 경로와 위험구간의 교차 횟수·정량 점수는 계산하지 않는다. 지오메트리 조회와 좌표계가 확인된 뒤에만 해당 분석을 별도 검토한다.
- 데이터 조회 실패·최신성 미확인·일부 응답 누락을 화면에서 구분한다. 누락을 안전 또는 시설 부재로 해석하지 않는다.
- 동행 가능 여부, 운영시간, 자격 조건은 공식 출처에서 확인된 내용만 안내한다. 불확실하면 공식 기관 확인을 안내한다.
- 긴급 상황의 구조·신고를 대체하지 않는다. MVP에서 긴급 신고를 자동 실행하지 않는다.
- 위치 입력은 경로 조회에 필요한 요청 처리에만 사용한다. MVP는 위치 이력·사용자 입력 원문을 서버 로그에 보존하지 않는다.

## 8. 데이터 및 외부 의존성

| 데이터/의존성 | 계획 | 미결정·검증 항목 | 실패 시 동작 |
|---|---|---|---|
| 행정안전부 생활안전지도 범죄주의구간(전체, WMS) | 생활안전지도 및 공공데이터포털에서 범죄주의구간 데이터의 공식 제공 출처를 확인. 검토 상세는 `docs/data-source-review.md` 참조 | 상세 데이터셋 ID, WMS endpoint·레이어·인증·이용약관·좌표계·갱신주기·지오메트리 지원 | 상세 검증 전 실제 레이어 연결·경로 분석 비활성. 제한 재시도와 누락 안내는 모의 테스트로 검증 |
| 보행 경로·지도 제공자 | 사용자가 실제 공급자 선택 전까지 모의 테스트에서만 사용 | 제공자, API 키, 보행자 프로필, 큰길·계단 옵션 지원, 호출 제한·비용 | 사용자용 실제 경로 조회는 비활성; 모의 응답은 테스트 화면/환경에서만 허용 |
| 조명·비상벨 안전시설 데이터 | 공식 데이터 포털을 확인했으나 실제 적용 데이터셋은 아직 확인되지 않음 | 제공기관, 데이터셋, 필드 의미, 위치 정확도, 갱신주기, 라이선스 | 데이터셋 검증 전 기능 비활성; 시설 부재로 단정하지 않음 |
| 공식 서울시 안심서비스/안심이 | 서울특별시 공식 홈페이지를 확인했으나 특정 서비스 페이지는 검증하지 못함 | 공식 서비스 페이지, 대상 지역·운영 조건·공식 URL·앱 딥링크 | 공식 URL 검증 전 버튼·딥링크 비노출 |

공공 데이터의 최신성·정확성·서비스 가용성은 본 제품이 보장하지 않는다. 경로 제공자가 선정·승인되기 전에는 모의 제공자를 장애 주입과 Auto Healing 검증에만 사용하며, 모의 결과를 실제 사용자 귀가 경로 또는 안전정보처럼 표시하지 않는다. 출처 검토 결과와 미확정 항목은 [데이터 출처 검토](./data-source-review.md)에 기록한다.

## 9. Auto Healing 설계

### 9.1 역할

| 역할 | 구현 방식 | 책임·권한 |
|---|---|---|
| Monitor | 규칙 기반 검사 | 헬스체크, 상태 코드, 시간 초과, 빈/잘못된 응답, 테스트 프로세스 상태를 감지하고 사건 생성. 읽기 전용 |
| Diagnosis | 규칙 기반 분류 | 근거를 `UPSTREAM_5XX`, `UPSTREAM_TIMEOUT`, `UPSTREAM_EMPTY_OR_INVALID`, `DEPENDENCY_UNREACHABLE`, `APP_PROCESS_DOWN`, `UNKNOWN`으로 분류. 복구 실행 금지 |
| Recovery | 제한된 코드 함수 | 정책이 허용하는 재시도, 안전정보 레이어 제한, Docker 실습환경의 허용목록 모의 프로세스 조치만 실행 |
| Verification | 독립 읽기 전용 검사 | 헬스체크, 응답 유효성, 핵심 기능·안내 메시지 테스트로 정상화 판정 |
| Orchestrator | 결정적 상태기계 | 순서, 시간 제한, 시도 상한, 중복 사건, 회로 차단, 에스컬레이션 관리 |
| Notification | 규칙 기반 알림 | 결과와 비민감 증거를 운영자에게 전달 |

역할 분리는 책임·권한의 논리적 분리이며, 모든 역할을 별도의 LLM으로 구현하지 않는다. LLM은 MVP의 복구 권한을 갖지 않는다.

### 9.2 장애·복구 정책

| 장애 | 자동 대응 | 검증 | 실패 시 |
|---|---|---|---|
| WMS HTTP 5xx/빈 응답 | 최대 3회 제한 재시도(초안 간격 1·2·4초), 이후 레이어 제한 안내 | 유효 응답, 출처·기준시각, 화면 상태 검사 | 회로 차단·운영자 알림 |
| 경로 API 타임아웃 | 최대 3회 제한 재시도, 이후 경로 미제공 안내 | 제공자 응답 형식·조건·이동시간 검사 | 대체 경로를 만들어내지 않고 에스컬레이션 |
| 시설 데이터 연결 실패 | 최대 3회 제한 재시도, 이후 시설정보 미확인 표시 | 데이터 출처·응답 유효성 검사 | 시설정보를 안전 판단에 포함하지 않음 |
| 테스트 프로세스 중단 | 격리 Docker 실습환경의 허용목록 모의 프로세스만 1회 재시작 | 프로세스 헬스체크와 기능 테스트 | 재시작 루프 없이 중단·에스컬레이션 |
| 반복 장애 | 같은 의존 서비스 3회 연속 복구 실패 시 회로 차단 | 차단 중 추가 호출이 없는지 검사 | 냉각시간 후 읽기 전용 확인, 실패 시 사람 검토 |
| 원인 불명 | 복구 없음 | 진단 근거 보존 | 즉시 사람에게 전달 |

수치(3회, 1·2·4초, 연속 3회, 냉각 60초)는 격리된 로컬 실습의 초기 제안값이다. 실제 제공자 정책·응답시간을 확인한 뒤 PRD 승인 시 확정한다.

### 9.3 권한 경계

**자동 허용:** 제한된 HTTP 재시도, 장애 레이어의 일시적 비표시, 격리된 Docker 실습환경에서 모의 프로세스의 허용목록 재시작.

**사람 승인 필요:** 운영 설정·API 키·제공자 변경, 운영 프로세스 재시작, 배포·롤백, 비용이나 데이터 처리 범위가 바뀌는 조치.

**금지:** 임의 명령 실행, 데이터 삭제·수정, 운영 시스템 변경, 인증정보 변경, 무제한 재시도, 검증 없는 정상화 선언, 자동 예약·긴급 신고.

## 10. 비기능 요구사항

### AWS 배포·운영 경계

- 애플리케이션은 Docker 컨테이너로 구성하고 AWS 클라우드에 배포한다. 컨테이너 실행 서비스, 리전, 네트워크, 배포 방식, 도메인·TLS, 로그 서비스는 미정이며 선택·승인 전에는 리소스를 생성하지 않는다.
- Day 3 데모는 사용자 승인과 계정·예산 한도 확인 후에만 배포한다. 불필요한 리소스는 종료 시 정리하고, 유료 API와 AWS 사용량을 제한·점검한다.
- 애플리케이션에는 필요한 범위의 최소 권한만 부여한다. Auto Healing 기능에는 AWS 리소스의 생성·변경·삭제 권한을 주지 않는다.
- API 키·인증정보는 코드·이미지·로그·브라우저 응답에 포함하지 않는다. AWS 비밀정보 관리 방식은 서비스 선택과 함께 확정한다.
- 위치 입력은 경로 요청에 필요한 최소 범위에서만 처리하고 장기 저장하지 않는다. 배포 리전과 외부 제공자 전송 여부를 확인한 뒤 데이터 처리 범위를 고지한다.
- AWS 로그의 저장 위치·접근 권한·보존 기간을 배포 전에 정하고, 사용자 좌표·입력 원문·API 키가 없는지 검증한다.
- PostgreSQL은 비민감 장애 운영 데이터 저장에 사용한다. 권장 데이터는 `incidents`(사건 ID, 의존 서비스 코드, 장애 유형, 상태, 시도 횟수, 발생·탐지·복구 시각), `incident_events`(사건 ID, 에이전트, 이벤트·조치·결과 코드, 시각, 소요시간, trace ID), `dependency_state`(회로 상태, 실패 횟수, 냉각 종료 시각)다. 원문 요청·응답, 출발지·도착지·정밀 좌표·경로 이력, API 키·토큰은 저장하지 않는다. 오류 근거는 비민감 요약 코드만 저장한다. 스키마, 접근 제어, 보존 기간, 백업 방식은 구현 전에 확정한다.

### 개인정보·보안

- 출발지·도착지·정밀 좌표·입력 문구는 장기 저장하지 않는다.
- 로그에는 사건 식별자, 서비스 식별자, 오류 코드, 시각, 비민감 검증 결과만 기록한다.
- API 키는 소스·로그·화면에 포함하지 않는다. 로컬 환경변수 또는 승인된 비밀 저장 방식을 사용한다(방식 미결정).
- 외부 제공자의 요청 제한과 이용 약관을 준수하며, 자동 재시도도 제한에 포함한다.

### 복원력·오류 표시

- 의존 서비스마다 별도 timeout을 둔다. 구체 값은 제공자 확인 후 정한다.
- 실패한 데이터와 정상 데이터를 UI에서 분리해 부분 기능을 유지한다.
- 캐시를 도입한다면 출처·수집시각·유효기간을 검증하기 전까지 사용자 안전정보의 대체 근거로 쓰지 않는다.
- 복구 상태·사용자 기능 상태·정보 누락 이유를 서로 혼동하지 않는다.

### 접근성·사용성

- 모바일 화면에서 야간에도 읽기 쉬운 명도 대비와 큰 조작 영역을 우선한다.
- 색상만으로 위험구간·장애·선택 상태를 구분하지 않는다.
- 지도 외에 경로별 텍스트 요약과 데이터 누락 안내를 제공한다.
- 이동 중 조작을 권장하지 않고, 화면 문구는 짧고 명확하게 유지한다.

## 11. 데모 검증 및 성공 기준

### 필수 시나리오

1. 정상 경로 조회와 범죄주의구간 레이어 표시.
2. WMS 5xx/빈 응답에서 제한 재시도 후 데이터 미수신 안내.
3. 경로 조회 타임아웃에서 최대 시도 횟수 적용 및 임의 경로 미생성.
4. 안전시설 데이터 연결 실패에서 시설정보 미확인 표시.
5. 반복 장애에서 회로 차단·자동 호출 중지·운영자 알림.
6. 모의 프로세스 중단에서 허용된 대상만 1회 재시작하고 독립 검증.
7. 사용자가 공식 앱 이동을 선택하지 않은 경우 앱으로 자동 이동하지 않음.
8. 로그·화면에서 출발지·도착지·API 키가 노출되지 않음.

### 측정 기준(초안)

- 3개 이상의 의존 장애 유형이 격리된 모의 제공자에서 재현 가능.
- 테스트 시나리오의 재시도 수가 정책 상한을 초과하지 않음.
- Verification 실패 시 사건이 정상 복구로 기록되지 않음.
- 모든 경로·안전정보 응답에 가능한 범위의 출처·기준시각이 표시됨.
- 데이터 누락을 안전함 또는 시설 부재로 표현하는 테스트가 0건.
- 격리된 모의 환경(로컬 또는 AWS 샌드박스)에서 MTTD ≤ 5초, 장애 주입부터 검증 통과까지 MTTR ≤ 15초를 목표로 측정. 측정값과 실행 환경을 보고서에 함께 기록하며, 실제 공공 API 가용성은 이 수치의 보장 대상이 아님.
