## 1. 승인 및 운영 규칙

- 이 파일은 PRD로부터 분해한 **작업목록 초안**이다. 사용자 승인을 받기 전에는 실행하지 않는다.
- 상태 표기:
  - `[ ]` pending
  - `[~]` in_progress
  - `[x]` complete
  - `[!]` blocked
  - `[-]` excluded
- 한 번에 하나의 하위 작업만 `in_progress`로 변경한다.
- 모든 구현 작업은 해당 기능의 테스트 코드를 함께 작성하고 실행한다. 테스트 없는 기능 구현은 완료 처리하지 않는다.
- 선행 작업이 완료되고 미결정 사항이 해소된 작업만 시작한다.
- 작업 시작 시 상태를 `[~]`로 바꾸고, 실제 테스트·검증 증거를 확인한 후에만 `[x]`로 바꾼다.
- 구현 세부에 영향을 주는 미결정 사항은 추측하지 말고 사용자에게 묻는다.
- AWS 리소스 생성, 비용 발생, 실제 배포는 별도 사용자 승인과 계정·예산 확인 전 금지한다.
- 실제 위치·경로 입력, 사용자 원문 요청/응답, API 키·토큰을 로그나 PostgreSQL에 저장하지 않는다.
- 현재 저장소에는 문서만 있으며 애플리케이션 소스·테스트·의존성 매니페스트는 아직 없다. 기존 문서를 먼저 읽고 작은 범위로 구성한다.

### DB-01 — PostgreSQL 사건·이벤트·의존성 상태 저장

- **상태:** `[ ] pending`
- **선행조건:** APP-01
- **관련 요구사항:** FR-08, Auto Healing 재시도·회로 차단, 로그 요구사항
- **예상 파일:** 마이그레이션, 저장소 코드, DB 테스트
- **작업:** 다음 권장 정보를 저장하는 최소 스키마를 구현한다.
  - `incidents`: 사건 ID, 서비스 식별자, 실패 유형/코드, 상태, 시도 횟수, injected/detected/recovery/recovered 시각.
  - `incident_events`: 사건/trace ID, 에이전트, 이벤트, 조치, 결과 코드, 시각, attempt, duration, 사람 승인 필요 여부.
  - `dependency_state`: 서비스 식별자, 회로 상태, 연속 실패 횟수, cooldown 종료 시각.
- **검증:** 마이그레이션 적용·읽기/쓰기·재시작 후 attempt/circuit state 유지 테스트. 위치·입력 원문·응답 원문·비밀정보가 스키마에 없는지 검사.
- **완료 증거:** DB 테스트 결과와 저장 필드 목록.
- **미결정:** DB 실행 위치, 계정·권한, 백업·보존기간은 DEC-04/운영 결정에 따른다. 민감한 원문이나 경로 데이터를 저장하지 않는다.

## 4. 작업 순서·승인 게이트

1. 이 작업목록을 검토하고 사용자가 승인한다.
2. DEC-01~DEC-04의 선택이 구현에 미치는 부분을 먼저 확정한다. 미정인 결정은 관련 구현을 차단한다.
3. Day 2 작업은 정상 기준선 → 사건/데이터 계약 → 모의 장애 → Monitor → Diagnosis → Recovery → Verification → Orchestrator → 통합 순서로 진행한다.
4. Day 3에는 AWS 구성 검증, 장애 실험, 측정, 보고를 진행한다. AWS 배포 작업은 이 작업목록 승인만으로 허가되지 않으며 별도 승인이 필요하다.
5. 각 작업은 한 번에 하나씩 진행하고, 테스트/실행 증거가 확보되지 않으면 완료 처리하지 않는다.
